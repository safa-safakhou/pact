# PACT administration — extension v2, 14 October 2026

Founder assignment: implement and deploy an administrator dashboard for observation and management. The founder subsequently explicitly required removing authenticator authentication completely from administration and using only username and password. This additive operator surface does not change game rules, player ownership, mandates, model budgets or experiment authorization.

Administration has its own `/admin` entry and username/password sign-in. Administrators use the existing identity module's `staff` role and server-owned `staff_auth_policy=password`, with a normal human session. There is no authenticator setup, code, recovery-code collection or five-minute MFA gate for administrators. Normal session expiry, active-account checks, sign-out/revocation, password hashing, login throttling, staff roles and CSRF still apply. Other staff retain the default MFA policy; players cannot edit staff policy or role. They do not need a player account, draft, kingdom, MCP grant or model connection. Operator usernames occupy reserved internal addresses at `operators.pact.invalid`; ordinary player signup, guest conversion and email changes cannot claim that namespace. These internal identifiers are not mail destinations.

Only a host-issued, random, private, expiring setup code can create the first administrator. The server enforces origin, bounded attempts, password policy and serialized one-time provisioning. First setup remains closed after provisioning, including if its account is subsequently removed during the setup code's validity. Subsequent provisioning/recovery is a controlled server operation; there is no public role editor. Administrator credentials remain private and are never retained in dashboard exports or telemetry.

The dashboard provides an overview, player directory, economy, society, agents, activity and management. All reads require a valid staff human session under its stored identity policy. Product-scoped module readers compose a repeatable-read, read-only database snapshot; reads have a statement timeout. The directory returns at most 25 public identities/activity metadata per page with bounded literal search. Aggregates include resources, production, contacts, retained message counts, offers/contracts/defaults, Courts, military operation counts, command outcomes, queue state, security event counts and agent execution metadata. Staff observation is audited through identity security events. No message bodies, private plans/memories, run objectives, credentials, grants or event payloads appear.

Time-window metrics explicitly identify their clock and population: player-session observations and command receipts use real timestamps, while game actions use committed game time. Run usage covers retained PACT runs created in the selected window, rather than claiming token consumption for all external hosts in that period. Current states and retained lifetime totals are labeled separately. Exact resource units retain the specified denominator of 600. Empty, stale, paused, failed and unavailable states are visible. Refresh is manual or every 30 seconds while the page is visible; snapshot export contains only those bounded overview aggregates.

Management uses the existing moderation queue and audited case handlers, honoring the same password-only identity policy for administrators, with normal CSRF, claims, evidence visibility, reasons and appeal restrictions. Administrator observation does not create gameplay authority. Clock changes, restores, deployments and further staff provisioning remain server operations. Independent Fleet state stays in Fleet; PACT can report its observed external activity and PACT leases without claiming Fleet budgets, continual execution or run certification.

Migration 0065 selects password policy and removes obsolete TOTP secrets, recovery codes and pending enrollments only for existing staff identities in the reserved operator namespace. Other player/staff MFA remains intact. The host setup code authorizes account creation once; normal sign-in requires only username/password.
