# 04 An Architecture for Autonomy

[Alami et al., 1998; author-hosted HAL manuscript](https://homepages.laas.fr/rachid/pdfs/archi/1997-ijrr-alami-hal.pdf). Coverage: all 39 PDF pages, using OCR because embedded text encoding is unreliable.

**Question and mechanism.** Sections 2–5 integrate functional services, a reactive executive, and planner/supervisor pairs. Modules own timestamped data and resource control; they report completion, failure, and interruption. Plans can contain constraints and monitored conditions, not just action lists.

**Evidence.** Section 6 describes three physical Hilare robots and simulations of up to thirty. A compiled executive example reduces 130 rules to a network with maximal depth eight. Different obstacle cases trigger local avoidance, local replanning, or renegotiation.

**Limits and contrary evidence.** Shared-data ownership does not establish cross-module semantic consistency. Reaction-time bounds require bounded event arrival and processing assumptions. Generator templates do not certify algorithm deadlines. The authors identify limited learning, uncertainty management, and human interaction as open problems.

**Mission implication — inference.** More modules demand explicit lifecycle, data semantics, and resource coordination. The showcased transport system uses a simple mission planner where a sophisticated one is unnecessary.

**Test suggested.** Measure event-overload behavior, interruption latency, and progressively escalated recovery; compare simpler planners before adding complexity.
