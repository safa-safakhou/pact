## 78 — Code as Policies: Language Model Programs for Embodied Control

**Source/coverage:** Liang et al., [arXiv v4, May 2023](https://arxiv.org/abs/2209.07753v4). Read main text pp. 1–6 and appendix pp. 9–12; remaining task examples, external prompts, videos and code not audited.

**Mechanism:** A code model generates executable programs using perception/control APIs, numerical libraries, loops and conditions. Undefined helper functions are recursively generated. The resulting program can run feedback control without consulting the model at every action.

**Evidence:** Hierarchical generation improves code-benchmark results. Simulated manipulation tests include unseen instructions/attributes; real drawing and manipulation examples are demonstrations rather than quantitative evaluations. A supervised policy performs better on the familiar spatial task family.

**Limits/contrary evidence:** Requires suitable APIs, careful prompts and pretrained perception. Weak-model improvements are inconsistent; hierarchy can reduce some generalization scores. Long or unfamiliar abstractions fail. Instructions are assumed feasible, correctness is unknown before execution, and automatic code repair was unreliable. Reactive-control examples are simplified and do not establish general controller synthesis. Filtering selected Python constructs is not evidence of behavioral safety.

**Mission implication — inference:** Reusable executable procedures offer an alternative to fixed pretrained skills or continuous model deliberation. Their termination, resource use, action validity and outcome monitoring still need explicit evaluation.
