# 11 An Analysis and Comparison of ACT-R and Soar

[Laird, ACS 2021; arXiv copy 2022](https://arxiv.org/abs/2201.09305). Coverage: all 18 pages; linked formalization not reviewed.

**Mechanism and comparison.** Both architectures distinguish agent knowledge, architecture-maintained metadata and module-status feedback. ACT-R restricts working memory to buffers; Soar permits an expanded graph and impasse substates. Their rule granularity, compilation and episodic storage differ despite similar high-level diagrams.

**Evidence type.** Detailed architectural analysis by a Soar developer, not a controlled performance comparison. The paper explains mechanisms and design tradeoffs; it does not establish which architecture plays games better.

**Limits and contrary evidence.** Similarity does not permit straightforward program translation. Human-memory constraints can increase implementation effort for complex agents. Reward rules remain problematic for novel tasks. Confidence, introspection and longer-term time judgments have gaps.

**Mission implication — inference.** Interface semantics matter as much as module names: commands, observations and execution status must be distinguishable. A decision module should observe execution success rather than create that success record itself.

**Test suggested.** Compare recovery from unavailable skills, delayed actions and failed retrievals, controlling both task knowledge and interface implementation.
