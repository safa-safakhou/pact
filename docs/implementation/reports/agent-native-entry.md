# Agent-native Alpha entry progress

Date: 27 September 2026. This is a post-completion PACT-049 tool-registry improvement, not a claim that PACT-054, PACT-059, PACT-062, or the PACT-079 external-client certification is complete.

## Problem observed

The first three Codex Envoys could act, but only after the operator supplied kingdom UUIDs, counterpart IDs, resource scaling, and supply-action payloads. That is not a usable agent gateway. The player should be able to state an objective to a connected agent and let it discover its own state and learn the rules from PACT.

## Increment delivered

- `pact_agent_guide_v1` is a read-only MCP entry tool for `world:read` grants. An empty argument object resolves the kingdom from the authenticated OAuth account; no caller-supplied identity or kingdom UUID is accepted. It returns a bounded owner snapshot, integer-marked balances plus floor whole units, contacts, pending requests, open/active supply and garrison agreements, and the existing mandate's actions and limits. It omits counterpart message bodies and request notes, labels player-controlled names as untrusted, and never opens a write lease.
- The same tool serves `development`, `diplomacy`, `military`, and `authority` lessons. Static rule values come from the current `rulesCatalog` in the PACT API, not copied numerical constants in a prompt. Examples are action shapes, with placeholders explicitly identified; they do not bypass the shared command dispatcher. The prior incorrect suggestion that scouting requires explicit unit UUIDs was corrected: the engine selects two available Spearmen when IDs are omitted.
- The game action tool points newcomers to the guide. The [MCP API](../../api/mcp.md) and [Codex playtest runbook](../../operations/codex-playtest.md) now present an ordinary one-sentence player objective instead of a long mechanical prompt.
- A first unaided Luna run showed that the agent tried to queue a Farm upgrade despite an existing waiting Farm instruction. The guide now exposes busy building kinds and near-capacity resources and teaches the one-instruction-per-kind and Hall-level rules. `BUILDING_BUSY`, `SLOT_BUSY`, and `INVALID_LEVEL` are preserved as actionable construction denials by the shared dispatcher rather than flattened to `INVALID_COMMAND`.
- A second unaided Luna run correctly chose a Storehouse upgrade after reading the revised guide, but its `run.open` was denied because the first exited CLI session still held its 15-minute write lease. MCP `DELETE /mcp` now closes the authenticated session and releases only that session's matching lease. The proposal path also returns an expected `FORBIDDEN` tool result when a lease is missing instead of an HTTP 500. A third fresh Luna session succeeded with the same plain-language objective and no supplied IDs or action shape.

## Boundary and remaining gap

The new guide uses a product-owned reader injected into the reusable MCP transport. It derives the account only from the authenticated principal, exposes no new write path, no other player's private reserves or messages, and no agent approval route. Contacts and pending offers are real owner-authorized records; it does not manufacture candidates. A player with no introduction cannot yet have an Envoy discover arbitrary strangers: exact-handle public profiles and notice discovery belong to dependency-gated PACT-054 and PACT-059, and richer objective-first context/result explanations belong to PACT-062. The agent must truthfully report that gap or ask for a real handle/invitation. The full agent-as-primary-UI experience is not complete until those pieces and a no-coaching playtest pass.

## Checks

Local Node 24 `npm run build`, `npm run typecheck`, `npm run lint`, `npm test` (124), and `npm run test:integration` (178) passed; after session cleanup and error-handling changes, the full suite passed again (124 unit, 178 integration). Unit tests verify owner resolution, 600:1 conversion, omission of counterpart prose, unfounded-account status, busy-building disclosure, and catalog-backed lessons. MCP integration verifies read-only listing, server-derived account, strict argument rejection, no write tool on a read-only grant, authenticated session close and lease release, rejection of another account's session, and a normal denial for a missing-lease proposal. VPS releases through `alpha-20260927-4` passed public `verify.sh`. Fresh GPT-6 Luna CLI sessions ran outside the repository, using only the account connection and the ordinary objective “Find out what my kingdom has and do one useful, safe thing toward securing more Grain.” The first learned the state but attempted a busy Farm. The second recognized the capacity constraint and chose Storehouse II, but the old orphaned lease blocked it. The third independently used the revised guide, opened its own lease, and committed `game.building.queue` for Storehouse II in slot 2, command `6b2b1432-441f-4f7e-8b88-294ea921130f`, charging 36,000 marked Iron and 18,000 marked Silver (60/30 whole). A read-only VPS PostgreSQL check found the instruction `active` in slot 2 and the exact MCP lease `52b86416-e40e-4c55-841f-89c2adc4960d` released after Codex exit. The final run used GPT-6 Luna and 186,169 input tokens, 160,000 cached; lower-overhead client configuration remains worthwhile. The `pact_briar` and `pact_cinder` saved OAuth grants failed refresh with `INVALID_GRANT`, so those profiles need normal browser reauthorization before another multi-account playtest. This is one successful agent-led move, not broad player-discovery or external-client certification.
