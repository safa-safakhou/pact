# RL-P01: proof-bound refresh recovery

Founder authorized recovery fixes, deterministic validation, server deployment and Git pushes on 15 October. This first batch adds an opt-in `pact.refresh-recovery.v1` contract advertised in OAuth metadata. Legacy clients keep their single-use rotation behavior.

Before a refresh the client must durably save an independent random 32-byte `recovery_proof` with the original refresh credential. The token endpoint atomically rotates and stores an AES-256-GCM encrypted result, bound to product, client and parent credential hash. Only that independent proof plus the original credential can recover the same result, for ten minutes. Access lifetime is reduced by elapsed time; the child must still be unused/unrevoked and the account, client and grant valid. A newer rotation makes an old exact-proof request invalid without revoking the newer child. An old credential alone or wrong proof still invokes reuse protection. Explicit revocation is never bypassed. No token/proof plaintext is stored in the recovery table or logs.

Seven isolated OAuth integration tests passed after building the package: concurrent exact recovery, ciphertext/no-secret assertions, newer-child protection, explicit revocation, legacy reuse and expiry. These are synthetic tests, not real account recovery or provider qualification. Migration 0068 is additive; encrypted recovery rows cascade with the grant and will be pruned by the following privacy/runtime batch. Existing ambiguous refreshes without a saved proof cannot use this contract and still require same-account reauthorization. Server Agent17 is not reconnected by this implementation.
