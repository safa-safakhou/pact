# PACT-131 — ChatGPT transport reconnect correction, 6 October 2026

## Problem and correction

The founder reported successful ChatGPT installation and owner-world reads, followed by FORBIDDEN on both construction and exact-approval proposals. Read-only hosted inspection found one active recent OAuth connection with game:act and a kingdom mandate allowing construction. Its write lease had been opened once, while subsequent calls created separate MCP sessions. There were 22 open transport sessions and no live lease at inspection. The denial was not proof that gameplay permission was disabled.

Previously every initialize generated a fresh session ID. Consumer hosts can initialize a fresh transport between tool calls, so an explicitly opened lease remained attached to a prior session. Supported-protocol reconnects now resume a logical session within the same server-authenticated OAuth grant. Migration 0053 adds the grant foreign key and a unique open-session index; concurrent initialization uses atomic upsert. Standard authentication checks the OAuth token every request. Different grants, including grants for the same account, cannot stream/use/close each other's session. HTTP DELETE still closes the logical session and releases only its matching lease. Reconnect does not extend the 15-minute lease, start inference, or change human authority. The ChatGPT specification records this correction explicitly.

The MCP route now identifies a RunError FORBIDDEN lease denial and a DispatcherError carrying the matching lease reason with reason WRITE_LEASE_REQUIRED and directs the agent to run.open before retrying the original intended command. It does not recommend increasing a human mandate for a session/lease problem.
