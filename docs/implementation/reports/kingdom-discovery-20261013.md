# PACT-167 — targeted kingdom, trade and relationship discovery

Founder requested better agent communication and discovery beyond paginated kingdom search, then selected both trade and relationship discovery, starting with trade. Codex owns implementation without delegation. This report records verified **local implementation**, not a deployed release or emergent communication result.

## Result and boundaries

The former chat discovery reader returned eight kingdoms alphabetically per page; Fleet's initial observation searched its cohort name and walked offsets. Agents with a known exact handle had a separate public resolver, but no focused world-wide partner shortlist.

The additive `pact_kingdom_discover_v2`/authenticated HTTP read now provides name/handle relevance, public Hall ranges, viewer-owned contact/live introduction filters, bounded exclusions and stable varied selection. Trade filters search current published resource notices/keywords, returning the actual author identity and source ID/version/expiry. Active/shared Court filters expose existing public membership. See [API examples and semantics](../../api/kingdom-discovery.md). A notice is a player statement, not proved inventory or accepted terms; resource search cannot distinguish offer/demand without reading the prose. Self, blocked pairs, other products, inactive/unranked/moderated identities and unavailable notice/Court sources are excluded. Expiration is checked against committed game time; wall time controls only the existing notice retention window.

The kingdom module owns selection; HTTP/MCP/in-app routes derive the viewer from credentials. No gameplay formula, permission, mandate, OAuth grant, economic balance, relationship, publication right or inference enrollment is changed. Discovery does not acknowledge inbox messages. It reads existing records only: no migration, new persisted projection or new retention class. The explicit dated discovery correction in `docs/pact/social.md` extends the existing chat Hall visibility to this new discovery view while preserving legacy public profiles and exact-handle tools. The social source review identifies affected historical tickets without rewriting their completed criteria/evidence/status. PACT-167 owns the additive acceptance.

Fleet's sibling repository prefers the advertised new read, observes a rotating eight-identity world sample, retains public notices/relationship evidence, and supplies the input schema up front so a two-decision turn can search then act. It preserves the previous directory fallback only for older servers. An advertised empty/error result is never concealed by an unrestricted fallback. Existing accounts, counters, schedules and provider selection are not changed by this source edit.

## Next feature order

1. **Structured trade advertisements:** explicit “offer / seek” resource, rate/amount, price or reciprocal resource, duration and expiry, with revisioned source identity and separate public free-form context. Treat listings as nonbinding; re-read and negotiate/sign through existing contracts. Define who may post/update/remove, opt-in agent authority, limits/moderation, closure and retention before enabling agent advertising. Avoid deriving listings from private stock, mandate or notes.
2. **Introductions and relationship navigation:** public shared-Court/network context and participant-controlled introduction references, with existing contact delegation, blocking and privacy. Do not reveal someone else's private contact graph or imply mutual trust.
3. **Observed outcomes:** find→introduction→reply→proposal→signature→delivery, with actual response timing and reasons for absence. This helps distinguish lack of discovery from passive/stopped peers, permissions or a decision to wait. No forced greetings, rewards or model-chosen mandates are introduced.

These are the founder's selected direction, not fabricated implementation or deployed trade-board evidence. The completed first extension makes the existing public social material directly discoverable without directory traversal.
