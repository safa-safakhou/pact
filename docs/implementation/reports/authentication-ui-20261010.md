# PACT-144 — Persistent player access and focused navigation, 10 October 2026

The founder authorized implementing the authentication review, simplifying the Advanced UI, committing and releasing on the existing server. Guest access must survive same-browser returns and support another device without creating a second kingdom.

## Implemented

Generic human-session bootstrap restores stable session-bound CSRF in fresh tabs while retaining legacy tokens, HttpOnly cookies, seven-idle/30-absolute expiry and Origin checks. Guest save stages a verified email/password conversion in existing retained verification-token storage (migration 0055); confirmation converts the same account, disables its guest recovery key and preserves kingdom/history/OAuth grants. Pending credentials are cleared on use and follow existing token retention and cascading account erasure. Duplicate emails never merge owners; expired/replaced/replayed/conflicting claims fail closed. Verification retains the original recent-authentication clock. Local logout revokes only that session; sign-out-everywhere retains global revocation semantics.

Guest entry now offers registered sign-in, password recovery and existing-only guest restoration. Account exposes the private guest recovery code for storage on another device, verified conversion and session controls. Credentials remain private and out of URLs. Registered bootstrap and successful conversion clear obsolete browser guest keys. Existing-key automatic recovery fails closed rather than silently founding a replacement. Pending first-entry retries retain their original key.

The live-browser inspection also found a whole-game disclosure beneath an always-present Council iframe. That wrapper is removed: Council has its own visible navigation entry, alongside the four existing game areas and Account. Council remains the web landing view, while deep links select their game area directly; native/Telegram retain their existing four-area host contract. Game controls no longer appear as a giant expanded page below Council.

Kingdom's large Advanced disclosure is replaced with **Overview / Buildings / Army / Economy** screens. Overview keeps scene, quick builds, builder status, supply summaries, threats and keepsakes. Buildings owns queue/cancel controls; Army owns troop/training/upkeep/threats; Economy owns detailed stocks, forecasts and shared action charges. Resource totals remain visible across sections. Account/privacy controls have their own screen, linked from game navigation and Envoy. All authoritative command handlers remain unchanged.

The deployed private email route is captured SMTP. The UI explicitly says codes come from the operator; guest recovery provides immediate device portability without email. This release does not configure or certify real outbound email, expand production scope, change agent authority or alter any continuous-player pacing/model/state.

## Notification failure found by hosted acceptance

The first hosted synthetic verification test failed because no captured email arrived. The notification worker logged repeated batch failures and never reached security-email delivery. A diagnostic projection inside a rolled-back transaction identified `FORBIDDEN` at the optional notification service's verified-account lock. Guest game events were being handled as externally deliverable verified-account notifications; the rejection rolled back inbox projection and prevented every later batch phase, including verification mail.

Internal event enqueue now keeps active guest inbox transactions and records the event as seen, while producing zero external deliveries for unverified accounts. Subscription/settings APIs retain the verified-account guard. Security email and game projection/delivery now run independently, so failure in either phase does not starve the other. Logs identify phase and safe error code without private content. New tests cover guest inbox/seen-event preservation without external delivery/settings authority, and both directions of batch failure isolation. This repair addresses the actual hosted prerequisite failure rather than bypassing email verification.
