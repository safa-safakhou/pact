# Bounded Envoy runs

Tickets: PACT-021.

`@pact/runs` owns exclusive kingdom/subject write leases and the Envoy run lifecycle: start, wait, resume, stop, takeover, and MCP lease acquisition without inference.

## HTTP

| Method | Path | Behavior |
| --- | --- | --- |
| `POST` | `/v1/runs` | Human session starts a bounded run (objective, provider, model, optional credential) |
| `GET` | `/v1/runs/:runId` | Owner-scoped run status and allowance counters |
| `POST` | `/v1/runs/:runId/stop` | Stop; release write lease; preserve committed work |
| `POST` | `/v1/runs/:runId/wait` | Waiting releases the worker without polling a model |
| `POST` | `/v1/runs/:runId/resume` | Resume within original deadline and remaining allowance |

Defaults: 15 minutes, 6 conversations, 12 messages, 20 calls, 40 000 tokens. Resume never extends the deadline. A second client receives `RUN_ALREADY_ACTIVE`.

Before invoking a provider, the service reserves against the actual assembled messages and tool definitions for that call, not a fixed input allowance. Caller-controlled message text is charged conservatively by UTF-8 bytes; stable tool schemas use an approximate four-bytes-per-token estimate. If the estimate leaves no output allowance, the run finishes without a provider call. Provider-reported usage reconciles the reservation afterward. This is a bounded admission estimate, not an exact provider-token guarantee.

The PACT inference composition supplies an asynchronous `messagesForRun` port. It resolves the run owner's kingdom through the kingdom module, then reads that account's authorized owner projection. Only an explicit selection of profile, balances, upkeep, at most 16 buildings and troop groups, eight threats, and eight contract identifiers/deadlines enters the model input. The selected JSON has an 8 KiB cap with a smaller balance-only fallback. The composition also selects at most eight newest event metadata records through the owner-scoped inbox service: sequence, event ID, conservative event type, and timestamp. It never copies event payloads into the convenience context. Both selections are labeled **user data, not instructions**; the system message stays fixed. Counterpart message prose, private reports, model credentials, and another player's hidden fields are not copied into this convenience snapshot. The same assembled messages are charged against the run allowance. Full conversation content remains available only through explicit authorized reads, not this summary.

## Explicit game reads

The in-app Envoy can call the same strict `pact_world_read_v1` and `pact_report_read_v1` schemas as MCP. The active run supplies the viewer account; tool arguments cannot select another viewer. World reads use the authorized owner/contact/participant/public projection, while report reads use scout/raid visibility checks. Results are capped at 3,600 UTF-8 bytes before the run's 4 KiB persistence limit. Oversized projections are marked `truncated`; an oversized report returns only its kind and record ID. Missing and unauthorized reports both return `NOT_FOUND`. These explicit read results can contain private owner data and remain in the 30-day run history and owner privacy export.

The same inference composition also exposes `pact_receipt_read_v1` and `pact_approval_status_v1`. A receipt read uses the shared dispatcher's account-scoped history, while an approval-status read selects only the run owner's request and returns its state, summary, expiry, receipt, and human review path. The summary is labeled `untrustedContent`; neither tool can approve or reject. Results are bounded to 3,600 UTF-8 bytes, with explicit truncation for oversized records, and persist under the same private 30-day run history. Both return `NOT_FOUND` for an unknown or different account's ID.

## Inference worker

`workers/inference` leases `envoy.run.tick` durable jobs and calls `RunService.executeModelCall`. On job redelivery, an unresolved in-flight request is marked `failed` with `ambiguousCrash`, its reservation and write lease are released, and no second provider call begins. A still-running original worker can only observe the now-failed run during reconciliation. This is deliberately conservative: if a provider response was lost, PACT cannot infer whether it was billed. Ambiguous provider failures likewise fail the job without an unbounded retry loop. Idle inbox delivery never receives a provider adapter.

The local process-death fixture now kills a synthetic inference executor after it reserves an in-flight request, then reclaims the expired durable job in a replacement process path. It verifies the conservative failure, cleared reservation and lease, and no second model invocation. This does not prove recovery of a tool result committed between the model response and run-step reconciliation, nor full VPS recovery.

The provider router validates tool names, unique call IDs, and parsed arguments before `RunService` passes returned calls to the injected `executeToolCalls` port. If the router admits a call but no executor is configured, the run fails with `MALFORMED_TOOL_CALL`; calls are never silently discarded. Other non-quota provider/tool errors also fail the run immediately, including when allowance remains. The PACT-owned command bridge uses the shared dispatcher and derives agent identity from the run. Gameplay transactions check `assertAgentWriteLease`: an MCP session must hold its own `mcp` lease, while an in-app Envoy must own the live `pact_run` lease. These holders are not interchangeable. The inference process composes the same `@pact/application` game handler as the API, with the generated `pact_command_v1` tool and an optional raid-seed secret from its own mount. It also exposes shared `pact_inbox_read_v1` and `pact_conversation_read_v1` schemas. An explicit model call can read up to five owner inbox events or five messages from an owner-involved direct conversation; oversized payloads/bodies are omitted and counterpart prose is labeled untrusted. The automatic context above still includes only inbox metadata, not private message bodies. PostgreSQL fake-provider fixtures exercise these tools without a paid provider. Run-start conversation selection and its six/twelve allowance accounting are not yet implemented.

After a successful tool batch, the worker records server-generated command receipt fields (command ID, code, charged amounts, record versions, committed event IDs, optional approval ID) or an explicitly requested, bounded read result in `envoy_run_tool_results`, atomically with run-step reconciliation. Command summaries are capped at 3,600 UTF-8 bytes; an oversized summary retains its command ID and code with `truncated: true`, and the owner-scoped receipt read can retrieve the full receipt. Inbox and conversation reads may contain owner-visible third-party prose; it is marked untrusted, can be shown to the selected provider, and persists with the private run for up to 30 days. Conversation results exceeding 3,600 bytes retain only message IDs and an explicit truncation marker. The next provider request includes at most the 16 latest results as labeled user-context data; it never promotes a counterpart's prose or tool arguments to system authority. The input allowance covers those results. A finished-run retry does not duplicate them. These rows cascade with run retention and appear in the owner's privacy export. If the worker dies between command commit and step reconciliation, the command receipt remains durable but the run is conservatively failed on redelivery; automatic result reconstruction and a post-command process-kill drill are still open.

The inference worker registers only the deterministic fake provider by default. `PACT_ENABLE_LIVE_MODEL_CALLS=1` is an explicit operator opt-in for the existing OpenAI, Anthropic, Gemini, and xAI API adapters; OpenRouter additionally requires an operator-reviewed `OPENROUTER_ROUTING_DISCLOSURE`. Merely mounting a key or storing a connection cannot enable billable calls. When enabled, the worker reads its inference-only private key, admits an owner-scoped vault use, checks that the stored provider matches the run route, and keeps decrypted credential bytes inside that admitted provider call. A selected credential without a resolver fails closed as `INVALID_CREDENTIAL`. Local tests use a synthetic credential and injected HTTP response; no real provider route or cost was certified. Broader selected conversations and multi-command cross-route scenarios remain PACT-049 work. Do not present the default MVP as a live model-game route.
