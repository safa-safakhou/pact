# Admission and construction evidence

Owner `pact_world_read_v1` responses add `authority` (`pact.authority-observation.v1`), scoped to the authenticated account and snapshot game time. Resource entries use marked ledger units (600 per whole resource), distinguishing full ceiling, legacy/rolling spend, reservations, headroom and reserve floor. Spend releaseSchedule is in GAME milliseconds; reservations list actual commitment/subject/action/status and have no automatic expiry. No stock is reserved by this view or by a waiting construction queue. Public/foreign views omit authority.

`pact_decision_support_v2` building candidates add checks.admissionQuote (`pact.construction-quote.v1`). Select an actual current candidateId to obtain its whole quote. It separates admission blockers from immediateStart blockers, ordinary/founding debit provenance, stock/mandate/rules/tick/event versions, world pause and conditional authority relief. A changed authority snapshot changes candidate IDs. Unknown legacy authority is explicit; a read does not grant scopes, an exact human approval or command permission. Existing unit reads distinguish ordinary eligible troops and incomplete pages; Guard/aggregate counts do not certify eligibility.

Queue admission can succeed while stock/prerequisites/builders defer start. Actual command receipt, subsequent job lifecycle and fulfilled resource delivery remain distinct. Stale/racing state is rechecked in the normal atomic shared handler. Precommit errors preserve INSUFFICIENT_ALLOWANCE and TROOP_LIMIT; these are explicit noncommit responses and do not change published v1 receipt enums. Missing receipts never authorize replay or manufacture a pending command. Human routes retain existing exact approval and authority revision controls; neither tools nor agents can grant themselves an exception.
