# Raid randomness and pure combat

`@pact/kingdom` owns the transaction-bound raid seed store (`0028_raid_randomness.sql`). At declaration, it generates a 32-byte CSPRNG seed, commits SHA-256 over the fixed RFC 8785-key-ordered payload, and stores the seed with AES-256-GCM encryption and raid/version/product-scoped associated data. The 32-byte encryption key is injected into the rules worker from a server-only secret; it must be backed up separately and never sent to clients or logged. A declaration retry with the same raid ID returns the original commitment. Changing its rules version fails.

Public evidence omits the seed while committed. Resolution or cancellation is authorized by the [raid state machine](raids.md), then calls `reveal` within its gameplay transaction. That call decrypts once, verifies the stored commitment, records the worker access audit, and reveals the original seed and both deterministic HMAC dice. Replays return the same proof. A rollback leaves the seed hidden and removes the audit write. Seed evidence and its audit expire 180 real days after reveal; committed raids remain until resolved or canceled. Participant raid reports are included in privacy export.

Verify a published proof after `npm run build` with `node scripts/verify-raid-seed.mjs <proof.json>`. The fixed spec fixture is `tests/fixtures/raid-randomness.json`; it must print `PASS`. The verifier checks seed encoding, commitment, and both dice. The commitment does not prove the server did not search seeds before publication.

`@pact/domain` owns `calculateCombat`, a pure calculation over an explicit eligible-unit snapshot, wall, ordinary stock, chosen priority, and the two verified dice. It uses exact rational power/casualty arithmetic and internal resource units. It returns a typed participant trace: power, wall suppression, branch, fractions, owner-and-side casualty groups, lost immutable unit IDs, survivors, carrying capacity, loot taken, leader receipt, and overflow. It never reads a database or decides who is entitled to see that trace. The raid state machine takes the locked battle snapshot and commits casualties/loot/report atomically. Its public report omits participant-only fields.
