# Contacts, private messages, and direct transfers

`@pact/kingdom` owns `SocialService` and migration `0024_social_contacts.sql`. The service receives a transaction-bound client and an authenticated account ID; it resolves that account's ranked kingdom instead of trusting a caller-supplied sender. Every two-kingdom mutation locks the pair in UUID order. The first shared command actions—`game.contact.request`, `game.contact.answer`, `game.message.send`, and `game.transfer`—now reach these ports through `@pact/application` and the world admission transaction. Human controls use the authenticated account; MCP agents must first call `run.open` and present that exact live session lease, checked inside the game transaction. Agent messages are allowed under shared limits; agent transfers and cold-contact requests additionally require mandate exposure. The cold-contact fee consumes two Silver of `contact.request` authority in the same transaction as the ordinary-stock debit, action limit, request, and outbox event; an optional `mandateVersion` rejects stale authority. Contact acceptance/decline remains human-only. OAuth `game:act` by itself is insufficient. The command ID is the operation key and the committed game timestamp is server-supplied. Other social controls are not yet routed.

Cold requests carry at most 400 Unicode code points, expire after seven game days, and cost two ordinary Silver plus one of eight rolling daily requests only when enqueued. An incoming queue holds at most eight live pending requests. Acceptance establishes one contact; decline does not refund the fee. Direct-contact invitations for controlled tests use 192 random bits, a stored SHA-256 token hash, one redemption, and seven real days of validity; active and game-day issuance caps are 20. An invitation acceptance establishes contact without a cold-contact fee. It grants no contract, transfer, or authority permission. Owner revocation and idempotent reacceptance are supported.

Accepted contacts can exchange immutable private text of at most 400 Unicode code points. Per sender/recipient, four unread messages are allowed; a recipient's total unread agent-originated message queue is capped at 48. Only successful sends consume the shared 96/day outgoing-message counter. Recipients alone mark their incoming text read. Mute suppresses ordinary message alerts but not delivery or factual gameplay events. Either party's block reciprocally stops new cold requests, text, offers, and gifts and cancels pending requests, while existing operations remain intact. Supply/garrison offer handlers must call `assertDirectCommunicationAllowed` before creating or signing a new offer. The social outbox contains IDs and alert hints, not private message text.

One-off transfers require an accepted, unblocked contact and a positive whole Iron/Silver/Grain amount. The sender's ordinary stock is debited once; restricted founding grants and locked bonds never fund a gift. The recipient receives up to its ordinary storage cap; overflow is recorded as lost, not refunded or promised back. The transfer, its two ledger movements, rolling 24/day counter, and outbox event share one transaction. A replay returns the original result. No reciprocal transfer is inferred or scheduled. The outbox notification request is separate mechanical traffic and does not consume an outgoing-message allowance; audience-specific inbox delivery is a later channel integration.

Private messages and cold-request prose are deleted after 90 real days by the retention job. Direct transfer records are retained 180 real days; expired invitation hashes are removed after one day of tolerance. Account export includes participant messages, contacts, and transfers; kingdom erasure cascades owned rows. Apply `npm run db:migrate` before restarting the rules worker on the single VPS. Local synthetic PostgreSQL 17 tests cover queue prechecks, fees, bounds, blocking, replay, expiry, transfer overflow, and rollback. No hosted deployment or player validation is claimed.
