# Future authority exposure

`@pact/authority` owns migration `0027_future_exposure.sql` and the product-neutral `ExposureService`. Commitments are keyed by product/account and operation key, not model provider. One account-row lock serializes reservation, consumption, release, and immediate spend across clients. Resource values are exact internal units. Agent admission enforces the current mandate action, version when supplied, legacy spend, rolling 24-game-hour actual spend, and remaining reservations. Lowering a mandate does not revoke a signed reservation; it blocks new agent work. A waiting building also rechecks the current mandate version and action at start.

`authority_commitments` and its asset rows retain original, remaining, and spent exposure. `authority_spends` is actual-debit history. A consumed installment or bond moves only its actual amount from reserved to spent. Closing an offer, contract, or waiting build releases only its remaining amount, idempotently. Incoming transfers, bond returns, construction cancellation refunds, and failed bargains never create a negative spend event. Generic troop-count commitments and Grain future-upkeep reservations share the account lock; PACT-040 supplies the garrison lifecycle that calls them.

`@pact/kingdom` translates domain operations through `SupplyExposureAdapter`, `ConstructionExposureAdapter`, and `ImmediateExposureAdapter`. The rules worker composes these adapters. Agent supply signing reserves the full outgoing flow plus bond, bond posting consumes bond exposure, each installment consumes its actual debit, and terminal contract paths release the rest. Building queues reserve the full quote, recheck current mandate and floors before start, consume only ordinary costs, and release the allowance-covered difference. Agent direct transfers, training costs, and the two-Silver `contact.request` cold-contact fee use the immediate ledger. Recurring army upkeep is not charged again as a new autonomous purchase.

`ExactHumanPermitService` issues a 15-real-minute, exact one-use permit under a live human session or first-party human OAuth grant with `game:act`. It validates the action, operation key, asset amounts, troop count, and still-live human credential in the same transaction that creates a separately labeled `human_exception` commitment. Revoked grants fail. The rules worker composes this validator, and a real supply signature consumes it; an agent signature rejects a supplied human permit. Public gameplay command/approval routing is not yet exposed because the shared dispatcher still supports sandbox actions only. PACT-049 must issue and consume permits inside its authenticated command transaction across the supported surfaces. No client-supplied ownership field is proof.

Authority spends and closed commitments are included in account export and removed after 180 real days; expired permits are removed after one day. Apply the migration with `npm run db:migrate` before restarting the rules worker. Local PostgreSQL tests use synthetic accounts, sessions, and offers. No VPS migration, deployment, or live-player check was run.
