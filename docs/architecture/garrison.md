# Garrison contracts and operations

`GarrisonService` in `@pact/kingdom` operates inside the caller's PostgreSQL transaction. Migration `0029_garrison_contracts.sql` owns offers, signatures, contracts, and mutual-release signatures. The rules worker calls offer expiry and contract settlement at minute boundaries, then settlement again after upkeep/default capture. No external call runs inside those transactions.

The lender must own a ranked kingdom with Hall III. An offer lists one to four ordinary troop-type/count entries, a 1/6/24-hour duration, and optional whole-resource bonds. Each bond is capped by the detachment's marked recruitment value and shares the aggregate locked-bond storage cap with supply. Both sides sign the same offer version; an agent signature reserves future authority, including host visiting upkeep for the duration plus five lock minutes. Expiry or withdrawal releases unactivated signatures. Activation locks bonds, places the actual UUIDs at the host, and starts at acceptance time; the end is the strictly next minute boundary plus duration.

The host pays visiting upkeep only from ordinary Grain, even when its own troops may use a founding allowance. Actual debit consumes its reserved exposure. The first insufficient visiting-upkeep debit records host default; settlement queues return and transfers any host bond to the lender. Recall/return before expiry defaults the acting party unless both signed an early mutual release. Return, expiry, and seizure respect an existing battle lock. Pending exit excludes these UUIDs from new battle snapshots. Seizure requires the host's exact one-use human-session permit for `garrison.seize`, the contract-specific operation key, and all surviving UUIDs; it also requires free owned capacity. Ownership changes on the existing UUIDs, with no unit creation.

Operations should invoke `createOffer`, `signOffer`, `withdrawOffer`, `requestExit`, `requestMutualRelease`, or `seize` through an authenticated application command transaction when the public gameplay dispatcher is added in PACT-049. Do not accept account or kingdom ownership from client payloads. A caller must derive `accountId` from its credential. The periodic worker supplies game time; retrying the same signed offer or settled contract does not repost bonds. Run migration/bootstrap before starting the worker. If the worker pauses, no real-time expiration occurs; resume advances game-minute settlement. Closed offers and contracts are exported through privacy and purged after 180 real days.

PACT-044 finalizes overlapping battle resolution against these locks. PACT-048 calculates Fortune from current unit ownership, so seizure changes marked unit wealth once by ownership rather than a duplicate score credit. PACT-049 supplies the shared public command/approval surface; this module does not expose a direct client endpoint.
