# Kingdom-wide charges and action limits

`@pact/kingdom` owns `ActionLimitService` and migration `0023_action_limits.sql`. Founding creates full raid (3) and scout (4) pools. All counters use a ranked kingdom ID and committed game time; provider, run, client, account recovery, and device are not keys. The rules worker materializes charge regeneration in its boundaries phase. A gameplay command calls `spendCharge` or `recordSuccessfulAction` only after its own validation, inside the same transaction as stock, commitment, receipt, and outbox changes. A rejected command or rolled-back transaction has no charge/quota effect. The command ID should be the operation key; existing dispatcher receipts remain the public idempotency authority.

Charge status returns capacity, availability, and an exact next-regeneration/retry game timestamp. Spending from full starts the 8-hour raid or 6-hour scout timer at the committed timestamp. Later spends below full leave the timer unchanged. Regeneration restores one per complete interval; reaching full discards surplus and clears the effective timer. A regeneration due exactly at spend time applies first. `kingdom_charge_spends` preserves the exact result of a spent operation for retry, including after later regeneration.

The successful-action windows use `(now − window, now]`: 96 messages, 48 offer actions, 8 cold contacts, 24 transfers, 6 public posts per rolling game day, and 120 gameplay state reads per rolling game hour. The service returns the earliest retry timestamp at capacity. The public-post counter is shared across Articles, Seals, and stories. Open negotiations (12) and active notices (2) are simultaneous-state capacities that their owning modules must enforce when implemented, not rolling action events. The caller must also enforce the 400-code-point message bound and cold-contact fee; these are not charged by a quota reservation. Receipt lookup, account safety controls, credential revocation, and human authority controls do **not** call the gameplay state-read counter; transport abuse protection is separate. No gameplay command routes use this service yet; PACT-036/037/041/044 and client-facing handler tickets integrate it as those actions arrive.

Run `npm run db:migrate` on the single VPS before restarting the rules worker. A failed tick or command transaction rolls back counter changes. To investigate, inspect `kingdom_charges`, `kingdom_charge_spends`, and `kingdom_action_events` at the committed game timestamp, not wall-clock time. The action-event rows are kingdom-owned and cascade on kingdom erasure. PostgreSQL 17 synthetic integration tests cover exact boundaries, shared keys, replay, denial, and rollback. No hosted deployment or live gameplay validation is claimed.
