# Chronicle and opportunity notices

PACT-059 / Alpha. `ChronicleService` owns `0041_chronicle.sql`; `ChronicleFactReader` owns the publication-safe application receipt projection. Kingdom historical building consequences are supplied through `ChronicleOutcomeReader`, not by querying another module's tables. All human writes enter `POST /v1/social/commands` through the shared dispatcher/world admission. The receipt, publication, shared six-post/game-day quota and outbox commit together; replay returns the original receipt without publishing again. Two notices may be active; duration is 1–24 game hours. Expired notices disappear from discovery but their direct page truthfully says expired. Replacement checks the exact version and consumes publication quota; removal does not. Notice replacement requires a fresh preview.

`POST /v1/chronicle/preview` requires the human's session, CSRF and Origin. Send a strict selection: `type`, `title` (60 code points), `commentary` (1200), optional `courtHandle` (active membership required), and either `durationHours` for a notice or the owner's `factCommandId` and up to three deliberately selected public `sealIds` for a story. An optional notice `postId`/`expectedVersion` replaces that notice. The response shows exact identities, commentary, safe factual consequences, live selected Seal evidence and `previewDigest`. Publish with `pact.chronicle-command.v1`, a stable command UUID, and `{kind:"chronicle.publish",selection,previewDigest}`. Removal uses `{kind:"chronicle.remove",postId,expectedVersion}`. Recomputing the preview in the transaction rejects changed input, changed source facts, removed evidence and stale notice versions.

`GET /v1/chronicle/facts` is owner-only and lists at most 50 actual committed receipt choices, newest first. It exposes no payload, objective, charged balance or whole run. The factual projection states that an instruction committed, **not** that a pending build/trade/raid completed. A selected building record adds its actual historical completed/canceled/pending consequence at preview time. Published facts are that preview's snapshot, never live kingdom reserves/building inventory. Other typed private reports must be shared deliberately through a selected Seal, not silently expanded. Commentary is labeled untrusted, not engine truth. No model call is used.

`GET /v1/chronicle` and `pact_chronicle_read_v1` share the same bounded projection: optional `postId`, `type`, `authorHandle`, `courtHandle`, `offset`; newest first, 50 rows/page and `nextOffset`. Only deliberate publications appear; private history remains in the existing owner-only world/report view. Public readers need no login. MCP requires `world:read`, derives identity from the grant, and returns real author handles/IDs and human-decision paths, never authority to publish. Blocked author prose collapses for that authenticated viewer; engine facts and public evidence remain available. HTML uses escaped React text, not user HTML. All Chronicle API responses are `no-store`, with no expansion parameter or dynamic private metadata.

Stories store Seal IDs, **not copied signed/preview payloads**. Every read resolves current public evidence: removed, expired, compromised or hidden source status cannot resurrect omitted text. Public copies outside PACT cannot be recalled. Hosted removal is immediate; module export/deletion/prune hooks are registered, with 180-real-day retention. Court tags do not make a Court owner or moderator the publisher or grant control over the author's resources/evidence.

The web exposes a public feed, author/Court filters, opportunity discovery in People, actual receipt selection, exact preview and explicit human confirmation. `?post=<id>` works before login and opens Chronicle after connection. Copyable links are available after publication. The author can separately issue a bounded notice/story invitation through the existing invitation handler; the generated URL contains **both** `post` and `invite`. Tokens are returned once, never put in receipts or logs. A direct post link alone grants nothing. Notice invitation acceptance explicitly creates only a conversation with the issuer, respecting blocks; it never signs an economic offer. Story invitation acceptance records a view destination only, not contact/membership. Expiry/removal/revocation use existing server-bound draft/redemption rules.

No share-card art, growth analytics, platform moderation case workflow, production certification or new deployment is claimed. The simple copyable URL and visible actual destination are the Alpha implementation.
