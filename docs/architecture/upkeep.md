# Upkeep, hunger, and desertion

`@pact/kingdom` owns migration `0022_upkeep_hunger.sql`, `UpkeepService`, payer-level hunger state, and durable garrison-default hooks. `@pact/domain` owns the pure food-payer, exact per-minute cost, and deterministic 5% desertion selection functions. The rules worker calls upkeep after production and before contract/battle phases inside the authoritative tick transaction. No client calculates or settles upkeep.

Home, raiding, and scouting units use their original owner as payer; visiting defensive units use the host. The ledger spends ordinary Grain before the restricted founding allowance and spends all available Grain on an underfunded minute. State is keyed by food payer, so all troops fed by that kingdom share Hungry's 75% combat-power condition, including its visitors. A funded minute resets the shortage streak; Hungry clears only after 60 consecutive funded minutes. Warning emits at underfunded minute 120. Desertion removes 5% (rounded up) of each payer/original-owner aggregate at minutes 180, 240, 300, etc., allocated by type remainder and lowest immutable UUID bytes. Operational battle locks cannot prevent starvation; the troop row deletion cascades eligibility references. Later combat handlers must read `UpkeepService.state` for each detachment's payer when computing power.

The `garrison_upkeep_defaults` table records the first underfunded tick for each visiting detachment reference. A `garrison.host_underfunded.v1` outbox event carries newly defaulted references; duplicate ticks and subsequent shortage minutes do not duplicate it. PACT-040 must consume this hook to transfer bonds and queue return under battle-lock rules. The hook alone does not execute an unimplemented garrison contract.

Apply `npm run db:migrate` on the single VPS before restarting the rules worker. The migration is additive. Inspect `kingdom_upkeep_state`, `garrison_upkeep_defaults`, ledger movements with `upkeep:<payer>:<game-minute>`, and `upkeep.*` outbox events when investigating a tick. A failed tick rolls back all four; resume the world clock from the last committed minute rather than replaying wall-time downtime. Local checks use PostgreSQL 17 synthetic schemas. No hosted migration or gameplay validation is claimed.
