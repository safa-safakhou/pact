# Building queues

`@pact/kingdom` owns migration `0020_building_queues.sql`, pure prerequisite/deadline rules, and the transaction-bound `BuildingEngine`. The seven founding building rows remain the level source of truth. `building_instructions` stores one active and one waiting instruction per builder slot, rejects the same building in two live instructions, and records exact start/due/settlement times and paid Iron/Silver provenance IDs. Instructions are idempotent by UUID and scoped to the authenticated kingdom owner.

At admission, the engine validates the target is exactly one level above the installed level, checks the chosen slot and building for a live conflict, obtains an authority reservation through `ConstructionAuthorityPort`, and starts immediately only when a slot is free, prerequisites and funds are ready, and the authority port confirms start. Otherwise it remains visible as waiting; it does not reserve stock. At each committed game-minute boundary, due active builds complete first, then waiting instructions are retried in builder-slot order. Completion installs one level, settles both resource-cost records, changes production/storage rates when applicable, and writes one outbox event in the tick transaction. Active cancellation delegates the 50% original-category refund to the ledger; waiting cancellation releases authority without touching stock. Duplicate completions/cancellations cannot repeat effects.

The rules worker invokes the engine after founding-grant expiry and before production, matching the rulebook phase order. The production worker currently injects `FailClosedConstructionAuthority`: active completions are processed, but no new waiting instruction can start there. This prevents an unverified agent or human permit from silently authorizing work. A real transaction-bound authority adapter, exact human permit/agent reservation behavior, and API/MCP command admission are **not yet wired**. PACT-039 verifies final economic integration. Do not expose queue actions to clients until the authority and receipt path is complete.

The pure rules can be checked with `packages/kingdom/src/building-rules.test.ts`; PostgreSQL queue/rollback/retry behavior and all 35 legal upgrades are in `tests/integration/buildings.test.ts`. On the single VPS, migration `0020_building_queues.sql` must run before the updated rules worker. No deployed validation is claimed.
