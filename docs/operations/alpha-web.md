# Private Alpha web controls

The web root at `https://safa.dedyn.io/pact/` is the first human gameplay client. It uses the existing first-party session and CSRF-protected API; it does not run a separate game engine. Use synthetic test accounts only. The registration notice is temporary MVP test data, not a production legal identity. Verification mail is captured inside the VPS, so the operator must deliver each synthetic account's one-time token through a private channel. Do not put passwords or tokens in Git, Linear, screenshots, or logs. See [VPS deployment](vps-deployment.md) and [identity operations](identity.md).

The current text-first web release is `alpha-20260928-6` (28 September 2026 UTC). The web client provides an owner-only social board, training progress, per-slot construction status, battle summaries, persisted scout navigation, guarded player switching/refreshes, owner charge pools/deadlines, and a desktop/mobile layout. Live scout-charge exhaustion and a two-account garrison offer/sign/mutual-release flow passed in Chrome (garrison used successive sessions). The complete UI-only founding/play walkthrough remains in progress; do not claim the pilot gate from a build alone.

For three-account external-agent play, use the [Codex playtest procedure](codex-playtest.md). Its bounded human mandate control is on the Envoy tab; model inference in PACT remains a separate, default-off route.

Sign in, or create and verify a synthetic test account. An unactivated account saves its kingdom name and handle, submits a harmless sandbox echo, records the connection check, and presses **Found kingdom**. Founding is server-idempotent. Returning accounts read `/v1/kingdom/me` and the owner-scoped `/v1/world/kingdoms/:id` view. The browser keeps only the CSRF token in tab session storage; passwords are not persisted. Refreshing the world and inbox uses a 15-second fallback poll plus the authenticated inbox event stream.

The four tabs currently expose:

- **Kingdom:** server balances and versions in whole game units (600 internal units each), buildings and two builder slots with active game-time deadlines and waiting-state hints, living troops separated into defensive-only Home Guard and ordinary units, owner-only active training progress with the next game-time deadline and a cancel control, upkeep, active supply contracts, threats, and forecast assumptions. Construction and training deadlines use game time: a paused world does not advance them. Hall upgrades require Farm and Barracks at the target level and Storehouse one level below it; a queued Hall can wait for those levels.
- **Envoy:** owner inbox, exact approval preview/decision, account export and closure. Manual gameplay does not require a working model provider.
- **People:** contact list, incoming/outgoing requests with direct answer controls, messages, public kingdom lookup by ID, direct transfers, open supply/garrison offers with exact-version signing, active and past contracts with terms, scouting, garrison lending, and raids. Garrison rows state the host's upkeep duty and both bonds; the lender can withdraw an open offer, and either party can request mutual release or unilaterally recall/return active troops. A host can seize visiting troops, which publicly defaults its promise and forfeits its bond. Early unilateral exit also defaults the acting party. Sensitive game actions use an inline confirmation panel rather than a browser dialog.
- **Chronicle:** up to 20 recent own scouts with status/deadline and a direct completed-report button, plus recent own/participating raids with side, status, game-time deadline, ID, and a one-click resolved participant report. Both lists survive a reload. Committed event summaries and manual report lookup remain available. Scout reports present observed defenses, troop bands, and ordinary stock bands as readable cards. Resolved raid reports summarize winner, authorized losses, and loot, with the full proof/trace collapsed by default. Event IDs are not report IDs.

Copy the other player's kingdom ID from their own header for a first contact; thereafter choose the contact by name. Offer IDs and exact versions are read privately by the two parties from `GET /v1/game/social`, so no out-of-band sharing is needed. This endpoint requires a first-party human session, derives the owning kingdom server-side, and is not granted to bearer world-read clients. The current Envoy inbox remains an event stream, not the social-message inbox. Do not infer a counterparty's private stock from a public view. Every write is a shared `PactClient.prepareCommand`/`submitCommand` call. The server decides ownership, charges, available stock, locks, action limits, and receipts; a UI disable state is never authorization. A rejected command displays the server code rather than `INVALID_RESPONSE`. On an uncertain network response, reconcile the same command ID before retrying. **Switch test player** returns to the login form and is also needed to obtain a tab-local CSRF token when an authenticated cookie is reused in a new tab.

Chrome tabs in the same browser profile share the PACT sign-in cookie. Signing in a different test account in one tab changes which account another tab shows after reload; use distinct browser profiles/sessions for a simultaneous two-player walkthrough. The 27 September Briar/Cinder training observations used successive sessions, not concurrent sessions.
After a player switch in another tab, the previous account's CSRF token is invalid for writes under the new cookie. Sign in again in that tab or use the original authenticated tab; do not treat `FORBIDDEN` from stale CSRF as a game-rule denial.

The UI detects that cookie-backed kingdom change at refresh, clears private panels and the old CSRF token, and returns to sign-in. **Switch test player** pauses refreshes until sign-in succeeds and discards outstanding responses from the previous view; it is disabled while an action is being submitted. Refresh failures are separate from command receipts and clear after a successful owner read. The construction target is the selected building's next level, not a manually entered downgrade/skip; max-level and already-queued buildings explain their disabled button. Missing prerequisites or stock may still yield a valid waiting instruction under server rules. See the dated [UI progress](../implementation/reports/rules-ui-progress.md) for deployment evidence.

The Kingdom and People **Action charges** cards display owner-only scout/raid availability, capacity, regeneration interval, and the next game-time charge deadline (or Pool full). An empty pool warns explicitly; absent projection data never implies a full pool. `RATE_LIMITED` can mean either a shared rolling action limit or exhausted charges, so the notice points to these cards without claiming a unique cause. Changing clients does not refill charges, and paused game time does not regenerate them. Buttons remain guidance: admission and all debits belong to the shared server command handler.

Chronicle's **Your raids** rows show your leader/contributor/defender role, the exact committed battle-lock deadline, and scheduled resolution. Before lock, an attacker can use **Withdraw attack** without copying a raid ID. Leader withdrawal cancels the whole raid; a contributor withdraws only its own force. Neither refunds provisions or charges. Both direct and manually entered withdrawal paths show inline confirmation. At the exact committed lock boundary the direct control closes; defenders have no withdrawal control, and paused/pending states disable it. Older snapshots missing a role/deadline offer no guessed withdrawal permission. A server `EXPIRED` denial for withdrawal explains that the window is closed; even a stale enabled button cannot override it. These labels use game time, not a local-wall-clock countdown.

A `WORLD_PAUSED` command receipt can also mean the next authoritative tick is due but not yet committed; it does not by itself prove an outage. The notice preserves the command ID and explains that the action did not commit. Refresh before deciding to retry; the client never silently resubmits it. An uncertain network result still requires exact-command receipt reconciliation, which is a different path. One-off transfers share a 24-successful-actions-per-rolling-game-day limit; this is not reset by signing in again or changing an agent.

This is a work-in-progress PACT-048 surface. It has not passed the required full two-player UI-only founding/play walkthrough or a complete accessibility audit. A focused deployed Chrome/IAB check found no unlabeled native controls, missing image alternatives, or visible targets under 44 CSS px in the four game areas, and keyboard Enter activated navigation; this does not certify WCAG 2.2 AA. First contact still requires a kingdom ID; there is no public kingdom discovery directory. Own scout/raid reports are now discoverable in Chronicle without retaining an operation ID outside the game. Fresh kingdoms need ordinary stock to accrue before training or paid contact; the founding allowance pays for construction only. Do not advertise this as a certified public release.
