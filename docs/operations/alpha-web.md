# Private Alpha web controls

The web root at `https://safa.dedyn.io/pact/` is the first human gameplay client. It uses the existing first-party session and CSRF-protected API; it does not run a separate game engine. Use synthetic test accounts only. The registration notice is temporary MVP test data, not a production legal identity. Verification mail is captured inside the VPS, so the operator must deliver each synthetic account's one-time token through a private channel. Do not put passwords or tokens in Git, Linear, screenshots, or logs. See [VPS deployment](vps-deployment.md) and [identity operations](identity.md).

The current text-first release is `alpha-20260926-7` (26 September 2026). The web client now provides an owner-only social board and clearer desktop/mobile layout. The full two-account UI walkthrough remains in progress; do not claim the pilot gate from a build alone.

Sign in, or create and verify a synthetic test account. An unactivated account saves its kingdom name and handle, submits a harmless sandbox echo, records the connection check, and presses **Found kingdom**. Founding is server-idempotent. Returning accounts read `/v1/kingdom/me` and the owner-scoped `/v1/world/kingdoms/:id` view. The browser keeps only the CSRF token in tab session storage; passwords are not persisted. Refreshing the world and inbox uses a 15-second fallback poll plus the authenticated inbox event stream.

The four tabs currently expose:

- **Kingdom:** server balances and versions in whole game units (600 internal units each), buildings, two builder slots, training, upkeep, active supply contracts, threats, and forecast assumptions.
- **Envoy:** owner inbox, exact approval preview/decision, account export and closure. Manual gameplay does not require a working model provider.
- **People:** contact list, incoming/outgoing requests with direct answer controls, messages, public kingdom lookup by ID, direct transfers, open supply/garrison offers with exact-version signing, active and past contracts with terms, scouting, garrison lending, and raids. Sensitive game actions use an inline confirmation panel rather than a browser dialog.
- **Chronicle:** committed event summaries and report lookup by an operation/raid ID from a receipt or inbox event. Scout reports present observed defenses, troop bands, and ordinary stock bands as readable cards; other report types still fall back to structured data. Event IDs are not report IDs.

Copy the other player's kingdom ID from their own header for a first contact; thereafter choose the contact by name. Offer IDs and exact versions are read privately by the two parties from `GET /v1/game/social`, so no out-of-band sharing is needed. This endpoint requires a first-party human session, derives the owning kingdom server-side, and is not granted to bearer world-read clients. The current Envoy inbox remains an event stream, not the social-message inbox. Do not infer a counterparty's private stock from a public view. Every write is a shared `PactClient.prepareCommand`/`submitCommand` call. The server decides ownership, charges, available stock, locks, action limits, and receipts; a UI disable state is never authorization. A rejected command displays the server code rather than `INVALID_RESPONSE`. On an uncertain network response, reconcile the same command ID before retrying. **Switch test player** returns to the login form and is also needed to obtain a tab-local CSRF token when an authenticated cookie is reused in a new tab.

This is a work-in-progress PACT-048 surface. It has not passed the required full two-player browser walkthrough or a deployed accessibility check. First contact, raids, and reports still require a kingdom or operation ID; there is no public kingdom discovery directory. Fresh kingdoms need ordinary stock to accrue before training or paid contact; the founding allowance pays for construction only. Do not advertise this as a certified public release.

For a harmless authenticated smoke without printing the test password, use `node scripts/smoke-alpha-api.mjs https://safa.dedyn.io/pact/ pact-mvp-owner@example.test /srv/pact/secrets/connection-test/operator_test_password` on the VPS. It reads the host-only password file, signs in through the public origin, checks the owner projection, submits a sandbox echo, reconciles its receipt, and reads the inbox. The command prints only a pass line and kingdom ID.
