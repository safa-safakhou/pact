# Dedicated PACT host

PACT runs directly at **https://pact.tinyagenttools.com/** on `root@2.31.62.91`. Cloudflare hosts the DNS-only A record pointing to that IP; Caddy on the new host terminates HTTPS with an automatically renewed Let's Encrypt certificate. Public base and OAuth issuer are both `https://pact.tinyagenttools.com`, and the MCP endpoint is `/mcp`. [Server migration](../implementation/reports/server-migration-20261008.md) and [direct subdomain cutover](../implementation/reports/subdomain-migration-20261008.md).

## Routing and existing accounts

The apex domain and `www` remain on `2.28.57.254` for Tiny Agent Tools. DNS cannot route an individual URL path to a separate IP. PACT's new hostname avoids that shared edge completely. The public edge uses `infra/production/pact-subdomain.caddy`, installed at `/srv/pact/config/edge/Caddyfile`; ports 80/443 are public. PostgreSQL, Mailpit and workers have no public listeners. Gateway HTTP remains on loopback and a private WireGuard address.

The old `/pact/` browser entry serves a guest sign-in handoff. In the same browser where the kingdom was played, choose **Continue with my kingdom**. A hidden new-origin frame receives the cached guest entry key via an exact-origin, exact-window message, resumes an existing account only, verifies the returned account identity and stores its key at the new origin. No key appears in a URL, report or server access log. Unknown keys cannot create replacement kingdoms through this handoff. Email-account users sign in normally on the new site. No authority allowance or approval is changed.

Existing ChatGPT installations still contain their old MCP URL. Reconnect them using **https://pact.tinyagenttools.com/mcp** after carrying the kingdom over in the same browser. OAuth discovery, authorization, token, revocation, signing-key and approval URLs generated by the new server use the new origin. A cached old connection is not evidence of certification of a new installation.

Temporary legacy API/MCP paths still cross the old edge over WireGuard for old clients. That compatibility path depends on the old host; new-domain browser, API and MCP requests do not. Old Telegram Mini App entry pages redirect to `/telegram/` on the new origin. The exact legacy webhook is not redirected. Update the BotFather named Mini App URL separately when retiring its old entry link; no bot conversation was sent here.

The stable old-edge configuration is `/srv/tiny-agent-tools/ops/pact-ingress.caddy`, mounted with `/srv/tiny-agent-tools/ops/compose.pact-edge.yaml`. It also mounts the source handoff directory. Preserve these files during root-app releases until legacy clients have moved. Repository references are `tinyagenttools-toolbox.caddy`, `tinyagenttools-pact-edge.yaml` and `browser-transfer/source.html` under `infra/production`.

WireGuard `pact` is enabled on both hosts: old `10.77.0.1/30`, new `10.77.0.2/30`, UDP 51820, each peer permitting only the other's tunnel address. Private keys remain in root-only `/etc/wireguard/pact.conf`. Docker requires that local interface before starting its private gateway listener; it does not need the remote host for direct-domain traffic.

## Old host and rollback

All old `pact-connection-test` services, including PostgreSQL, remain explicitly stopped, and its backup timer is disabled. Historical volumes, secrets and backups are preserved. Do not start this frozen world alongside the new live world. Testing needs a distinct Compose project, fresh identity/encryption credentials, synthetic data, separate URLs/callbacks and no production Telegram token or live inference by default. No test world or population experiment was started.

Application rollback changes images on the new host, preserving current data. The previous gateway uses `/pact/` assets, for which the new edge retains a compatibility alias. It lacks the existing-only guest handoff; remove that handoff during a full release rollback rather than accepting recovery requests against the older API. Configuration before the subdomain change is protected at `/srv/pact/state/releases/pre-subdomain-production.env`; old-edge backups are `edge-before-subdomain-20261008.caddy` and `compose-before-subdomain-20261008.yaml` on the old host. Restoring an old origin requires coordinating configuration, assets, discovery and browser entry, not merely switching a DNS record.

After new writes, switching to the frozen old database would lose progress. A host rollback requires freezing new writes, copying current data and the deletion registry back, verifying the copy, and then routing traffic back. The historical ingress file alone is insufficient for live-data rollback.

## Council release and source packaging

The Council release adds migration `0054_council_characters.sql`, shared browser/MCP presentation, public appearance and observed activity. Existing permissions and economy remain authoritative. Use a fresh PACT tool result to load a new hashed ChatGPT UI resource; already-rendered messages keep their old view.

When archiving a macOS checkout, disable AppleDouble metadata and include only tracked/non-ignored source:

```sh
git ls-files --cached --others --exclude-standard -z | COPYFILE_DISABLE=1 tar --no-xattrs --null -T - -czf /tmp/pact-source.tar.gz
```

Check extracted source for `._*` metadata before building. Docker also excludes `**/._*`. Metadata files ending in `.sql` can otherwise be mistaken for migrations. A release must pass the normal migration runner before application containers switch. Preserve the current/rollback images and encrypted backup before applying schema changes.
