# Offline society acceptance

`node --import tsx scripts/evaluate-agent-society.ts` emits deterministic synthetic JSON. It imports shared game action validation and exact supply authority exposure, but has no database, credential, provider, URL-fetch or scheduler port. Running it never starts production players, unlocks a route or spends a model allowance.

The versioned dataset contains two development families and ten held-out families with two synthetic adjacent-turn snapshots each. Whole scenario families and episode identities stay in one split; duplicate turns, cross-split adjacent families and missing outcome trajectories fail validation. Policies receive the same cloned owner goal, permitted facts, peer statements and candidate checks. Hidden fixture outcome trajectories are withheld. Explicit owner utility values are scenario assumptions, not a production ranking injected into agent context.

Scoring separates valid response, empty plan, unsupported/stale/unaffordable/unauthorized choice, failing replay, repeated statements and supplied compute counters. Accepted choices are evaluated against their **synthetic** trajectories: goal result, justified wait, useful outcome, changed terms, activation, delivery and default. Statement count has no reward; allowed in-game bluffing and threats remain text, not new authority. Neither cooperation nor attack is inherently preferred: the owner's explicit goal and feasible current facts determine the fixture score. Exact outgoing exposure is an authority reservation, not guaranteed peer performance.

Default policies are `calculated-choice`, `candidate-baseline`, `reference-script-fixture` and `model-response-fixture`. The latter two are deliberately synthetic controls, **not recordings of the current fifty-owner model or a real intelligence comparison**. The policy hook accepts already-authorized synchronous owner-supplied replays; unknown action fields cannot invoke tools, and failing hooks produce a typed failure without copying private errors. Reported token counters are supplied, not independently verified usage or money; the built-in harness makes zero model requests. Freeze the dataset hash/splits before a separately authorized real benchmark, retain its exact route/bounds, and never publish real private transcripts with results.

`npm test -- tests/unit/agent-society-evaluation.test.ts` verifies the scorer. `npm run test:integration -- tests/integration/agent-society-load.test.ts` creates isolated disposable database schemas for 20/50/100 accepted relationships, full Unicode delivery and cursor history, private memory, both-owner named observation, revocation and real retention. It emits body-free local read latency aggregates. This is service acceptance at one owner per fixture, not live simultaneous-agent/GPU capacity. Existing supply/authority/military integration suites separately verify actual command/settlement receipts; fixture trajectory counters must never be advertised as new game actions.

Real local/Codex/consumer-host model comparison and a population pilot require their accepted route, owner enrollment, explicit request/spend bounds and observed receipts. PACT-155/156/158/159 own those gates; JSON validity, a static score, or a fast read does not satisfy them.
