# Private strategy and relationship memory

PACT-153 stores concise owner/Envoy-authored notes separately from game facts. Types are assessment, strategy, goal, milestone and question. Exact topics and an optional public counterparty ID support retrieval; neither a strategy note nor the legacy freeform ambition field changes authority. Models must not store hidden chain-of-thought or another owner's private plan.

Human clients use `GET/POST /v1/game/private-memory`; writes require the owner's session, CSRF token and allowed Origin. MCP exposes `pact_private_memory_read_v2`, `pact_private_memory_write_v2` and `pact_private_memory_source_v2` under read/write grant scopes. In-app runs expose read/write and reuse existing participant source readers; a write rechecks the running lease inside its transaction. No credentials or caller-provided ownership/audience are accepted. The Envoy workspace provides a private relationship/topic view, corrections, revision history and source checks.

Every write uses an entry ID, expected revision and exact command ID. Same-request replay returns its original committed revision, even after superseding/pruning; changed command payloads conflict. A stale revision writes nothing. The browser stores an uncertain exact request in owner-keyed tab storage before POST and blocks edits until its outcome is resolved. This pending request is tab-local; committed notes are server-side and survive host/model/device changes. Another device must reload the current revision before correcting it.

Each revision includes author kind, observed game time, rules version and up to eight distinct authorized source pointers. Message/offer/contract/military/build/receipt metadata is reauthorized when inspected; existing projections deliver full facts/transcripts and enforce current visibility. A pointer never grants source access or acknowledges a message. Missing/purged/unauthorized records return unavailable. Garrison pointers can refer only to their retained current terms; supply term versions use the retained history. Database source status is not an actionable quote: current projections own effective expiry and permissions.

Lists/history use stable cursors, twenty-record lookahead and a 36,000-byte full-entry bound. No body is silently excerpted. Notes accept up to 8,000 UTF-16 units, 28,000 serialized bytes and a one-MiB per-owner retained-body/source budget. Initial in-app context includes at most 6,000 bytes of complete notes with explicit omission and a full-read tool; empty memory adds no prompt. Private memory cannot provide model intelligence or establish useful bargaining by itself.

Current active notes persist until deletion/account forgetting. Superseded/deleted revision content is pruned after thirty real days; lightweight exact-request hashes/version receipts remain until account forgetting. Export includes only owned notes/revisions. Account erasure removes owned entries and clears peer references in other owners' note headers, without changing immutable gameplay receipts or their existing retention policy. No transcripts, public memory index or hidden reasoning are auto-copied into this store.

Migration `0060_private_memory.sql` creates empty tables and grants no permissions/enrollment. The fifty-owner native task stays stopped; private-memory tools do not start or schedule inference. Captured-email, physical-device and external chatbot-route acceptance limitations remain separate.
